# ระบบใบเสนอราคา — บริษัท เอส แอนด์ เอส อินคอม จำกัด

เวอร์ชันสำหรับรันบน **Railway** ด้วย **Python FastAPI + PostgreSQL**
หน้าเว็บเป็นชุดเดียวกับที่ใช้อยู่ (ทะเบียน · ประวัติราคา · ฟอร์มออกใบ · นำเข้า .docx/.csv/.xlsx ·
พิมพ์ PDF · ดาวน์โหลด Word) ต่างกันตรงที่ข้อมูลย้ายไปอยู่ในฐานข้อมูล PostgreSQL ของคุณเอง

---

## ทำไมต้องย้ายทั้งแอป ไม่ใช่แค่ฐานข้อมูล

หน้าเว็บที่ Claude โฮสต์ให้ถูกบล็อกไม่ให้เรียก API ข้ามเซิร์ฟเวอร์ จึงต่อ Railway ตรง ๆ ไม่ได้
ชุดนี้จึงเป็นแอปเต็มตัว — FastAPI เสิร์ฟทั้ง REST API และหน้าเว็บ โดยมี PostgreSQL อยู่ข้างหลัง

---

## ไฟล์ในชุดนี้

| ไฟล์ | หน้าที่ |
|---|---|
| `main.py` | FastAPI — REST API ทั้งหมด ล็อกอิน และเสิร์ฟหน้าเว็บ |
| `db.py` | asyncpg connection pool, migration และตัวช่วยแปลงค่า |
| `schema.sql` | ตาราง ดัชนี และมุมมองประวัติราคา (รันอัตโนมัติทุกครั้งที่แอปสตาร์ท รันซ้ำได้) |
| `public/index.html` | หน้าเว็บทั้งหมด (ไฟล์เดียว ไม่ต้อง build) |
| `seed_data.sql` | ใบเสนอราคาย้อนหลัง 2560–2569 ที่อ่านจากไฟล์ Word เดิม 167 ใบ — ใช้หรือไม่ใช้ก็ได้ |
| `requirements.txt`, `railway.json`, `Procfile`, `.python-version` | ค่าตั้งต้นสำหรับ deploy |
| `.env.example` | รายการตัวแปรที่ต้องตั้ง |

## ขั้นตอน deploy (ประมาณ 10 นาที)

1. **สร้าง repository** — เอาโฟลเดอร์นี้ทั้งก้อนขึ้น GitHub (เป็น private ได้)

   ```bash
   git init && git add . && git commit -m "ระบบใบเสนอราคา"
   git remote add origin https://github.com/<บัญชีของคุณ>/ss-quotation.git
   git push -u origin main
   ```

2. **สร้างโปรเจกต์และเพิ่มฐานข้อมูลก่อน** — railway.app → *New Project* →
   *+ New* → *Database* → *Add PostgreSQL*

   > **ทำขั้นนี้ก่อนเพิ่ม service ของแอป** แอปจะหยุดทำงานทันทีที่สตาร์ทถ้ายังไม่มี `DATABASE_URL`
   > (`db.connect()` ใน `db.py` ตั้งใจให้ล้มพร้อมข้อความชัด ๆ) ถ้าเพิ่มแอปก่อน deploy รอบแรกจะ
   > **fail แล้ว retry อีก 5 ครั้ง** ตาม `railway.json` — เป็นอาการปกติของการสลับลำดับ ไม่ใช่โค้ดพัง
   > ผูกตัวแปรในขั้นที่ 4 แล้วกด *Redeploy* ก็ขึ้นปกติ

3. **เพิ่ม service ของแอป** — ในโปรเจกต์เดียวกัน *+ New* → *GitHub Repo* → เลือก repo นี้
   (Nixpacks จะเห็น `requirements.txt` แล้วตั้งเป็นโปรเจกต์ Python ให้เอง)
   ถ้าไม่เห็น repo ในรายการ ต้องกด *Configure GitHub App* ให้สิทธิ์ Railway ก่อน

4. **ผูกฐานข้อมูลเข้ากับแอป** — เปิด service ของแอป → แท็บ *Variables* → *New Variable* →
   *Add Reference* → เลือก `DATABASE_URL` ของ Postgres

   ต้องใช้ *Add Reference* เท่านั้น อย่า copy ค่ามาวางเอง — reference จะได้ที่อยู่ภายในเครือข่าย
   Railway ซึ่งเร็วกว่าและไม่เสียค่า egress

5. **ตั้งรหัสผ่าน** — เพิ่มตัวแปรอีกสองตัวในหน้าเดียวกัน

   | ตัวแปร | ค่า |
   |---|---|
   | `APP_PASSWORD` | รหัสผ่านที่จะใช้เข้าระบบ (ตั้งเอง — ถ้าเว้นว่างจะเปิดให้ใครก็เข้าได้) |
   | `SESSION_SECRET` | ข้อความสุ่มยาว ๆ เช่นผลจาก `openssl rand -hex 32` |

6. **เปิดที่อยู่เว็บ** — *Settings* → *Networking* → *Generate Domain*

7. เปิดลิงก์ที่ได้ ใส่รหัสผ่าน — ตารางทั้งหมดถูกสร้างให้อัตโนมัติตอนแอปสตาร์ทครั้งแรก

8. **ตรวจว่าขึ้นจริง** — ใน *Deploy Logs* ต้องเห็นสามบรรทัดนี้เรียงกันตอนสตาร์ท

   ```
   กำลังเชื่อมต่อฐานข้อมูล postgresql://postgres:***@... (ssl=off)
   เชื่อมต่อสำเร็จ: database=railway user=postgres · PostgreSQL 16.x
   schema พร้อมใช้งาน
   ```

   แล้วเปิด `/healthz` หลังล็อกอิน จะได้ JSON บอกรายชื่อตารางและจำนวนข้อมูลในแต่ละตาราง
   ใช้ยืนยันได้ว่าโค้ดที่รันอยู่เป็นเวอร์ชันล่าสุดจริง และต่อฐานข้อมูลถูกตัว

### ลองรันในเครื่องก่อน (แนะนำ)

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export DATABASE_URL="postgresql://..."                # ของ Railway หรือ Postgres ในเครื่อง
export APP_PASSWORD="ทดสอบ"
uvicorn main:app --reload                             # เปิด http://127.0.0.1:8000
```

เอกสาร API อัตโนมัติของ FastAPI อยู่ที่ `/api/docs`

## นำเข้าข้อมูลเก่า — เลือกทางใดทางหนึ่ง

### ทาง ก. ผ่านหน้าเว็บ (ได้ตรวจทานก่อนบันทึก)

แตกไฟล์ `Quotation_DOCX_2560-2569.zip` แล้วลากไฟล์ `.docx` เข้าหน้า **นำเข้า / ส่งออก**
ระบบจะอ่านมาพักในตารางตรวจทาน แก้เลขที่/วันที่/ชื่อลูกค้าได้ แล้วกด **บันทึกเข้าฐานข้อมูล**
(ยิงไปที่ `POST /api/quotations/bulk` บันทึกทั้งชุดในทรานแซกชันเดียว) ลากทีละปีได้

### ทาง ข. กดปุ่มในแอป (เร็วที่สุด ไม่ต้องลงเครื่องมืออะไรเพิ่ม)

หน้า **นำเข้า / ส่งออก** → ปุ่ม **โหลด 167 ใบที่มากับระบบ**

`seed_data.sql` ถูก deploy ไปพร้อม repo อยู่แล้ว ปุ่มนี้ยิงไปที่ `POST /api/seed`
ให้เซิร์ฟเวอร์รันไฟล์เข้าฐานข้อมูลของตัวเอง แล้วตอบจำนวนแถวก่อน/หลังกลับมาแสดงในกล่อง log

ไฟล์นี้รันซ้ำได้ ใบที่ **เลขที่ + วันที่ + ลูกค้า** ตรงกันจะถูกอัปเดตทับ ไม่เกิดข้อมูลซ้ำ
และไม่มีการลบข้อมูลเดิม — กดซ้ำครั้งที่สองจำนวนใบจะไม่เพิ่ม

### ทาง ค. รัน SQL เองผ่าน psql

สำหรับคนที่มี [Railway CLI](https://docs.railway.com/guides/cli) และ PostgreSQL client
(`psql`) ติดตั้งไว้แล้ว — ได้ผลเหมือนทาง ข. ทุกประการ

```bash
railway link                  # เลือกโปรเจกต์
railway connect Postgres      # เปิด psql
\i seed_data.sql

# หรือใช้ connection string ตรง ๆ
psql "$DATABASE_URL" -f seed_data.sql
```

## REST API

ทุกเส้นทางต้องล็อกอินก่อน ยกเว้น `/api/login`, `/api/logout` และ `/healthz`

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| `POST` | `/api/login` | ส่ง `{"password": "..."}` ได้คุกกี้เซสชัน |
| `GET` | `/api/bootstrap` | โหลด config + ลูกค้า + สินค้า + ใบเสนอราคาทั้งหมด |
| `POST` | `/api/quotations` | บันทึกใบเดียว (มี `id` = แก้ไข, ไม่มี = สร้างใหม่) |
| `POST` | `/api/quotations/bulk` | บันทึกหลายใบในทรานแซกชันเดียว `{docs: [...], replace: bool}` |
| `DELETE` | `/api/quotations/{id}` | ลบใบ (รายการสินค้าและเงื่อนไขถูกลบตาม) |
| `POST` | `/api/seed` | รัน `seed_data.sql` ฝั่งเซิร์ฟเวอร์ ตอบจำนวนแถว `before` / `after` / `added` |
| `POST` / `DELETE` | `/api/customers`, `/api/products` | ทะเบียนหลัก |
| `PUT` | `/api/config` | ข้อมูลบริษัทและค่าตั้งต้น |
| `GET` | `/api/price-history?customerId=&productId=&status=` | ประวัติราคาคิดฝั่ง SQL |
| `GET` | `/api/latest-prices?customerId=` | ราคาล่าสุดของแต่ละคู่ ลูกค้า × สินค้า |

รูปแบบ JSON ของ API ตรงกับที่หน้าเว็บใช้ทุกฟิลด์ (camelCase) จึงเปลี่ยนแบ็กเอนด์ได้โดยไม่ต้องแก้หน้าเว็บ

## โครงสร้างฐานข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `quotations` | หัวเอกสาร — เลขที่ วันที่ ลูกค้า (snapshot ณ วันออก) อัตราภาษี ยอดรวม สถานะ |
| `quotation_items` | บรรทัดสินค้า ผูกกับ `products` ด้วย `product_id` |
| `quotation_terms` | เงื่อนไขการเสนอราคา เก็บเป็นคู่หัวข้อ–รายละเอียด |
| `customers`, `products` | ทะเบียนหลัก จับคู่ด้วย `name_key` (ชื่อที่ตัดช่องว่าง/จุด/วงเล็บออกแล้ว) |
| `company_config` | ข้อมูลบริษัทและค่าตั้งต้น เก็บเป็น JSONB แถวเดียว |

**เรื่องเลขที่หนังสือ** — ในเอกสารเก่ามีการใช้เลขที่ซ้ำข้ามลูกค้าอยู่จริง (เช่น `SS 1108/2561`
ถูกใช้กับ NPP9, NPS และ Weber ในวันเดียวกัน) ฐานข้อมูลนี้จึง **ไม่บังคับให้เลขที่ไม่ซ้ำ**
แต่กันซ้ำด้วย `dedupe_key` = เลขที่ + วันที่ + ลูกค้า และหน้าเว็บจะเตือนให้เห็นทั้งสองกรณี

**มุมมองสำเร็จรูปสองตัว**

- `price_history` — หนึ่งแถว = ราคาที่เคยเสนอสินค้าหนึ่งให้ลูกค้าหนึ่งในวันหนึ่ง
- `latest_price_per_customer_product` — ราคาล่าสุดของแต่ละคู่ (ลูกค้า × สินค้า)

```sql
-- เคยเสนอราคาลูกค้ารายนี้เท่าไหร่บ้าง
SELECT doc_date, no, product_name, price, unit
FROM price_history
WHERE customer_name ILIKE '%อายิโนะ%'
ORDER BY doc_date;

-- สินค้าตัวนี้เคยเสนอลูกค้ารายไหน ราคาเท่าไร
SELECT customer_name, doc_date, price
FROM price_history
WHERE product_name ILIKE '%0.125%'
ORDER BY doc_date DESC;

-- ราคาล่าสุดของลูกค้าทุกราย
SELECT * FROM latest_price_per_customer_product ORDER BY customer_name;
```

ค้นข้อความภาษาไทยใช้ดัชนี trigram (`pg_trgm`) เพราะ PostgreSQL ตัดคำไทยเองไม่ได้

## สิ่งที่ทดสอบแล้วและยังไม่ได้ทดสอบ

**ทดสอบแล้ว (กับ PostgreSQL 16 จริง)**

- `schema.sql` รันผ่าน และรันซ้ำได้ไม่พัง
- **คำสั่ง SQL ทั้ง 28 คำสั่งใน `main.py` ผ่าน `PREPARE` กับ schema จริงทั้งหมด** —
  ชื่อคอลัมน์ จำนวนคอลัมน์ และตำแหน่งพารามิเตอร์ถูกต้อง
- ทดสอบ upsert จริง: บันทึกซ้ำด้วยคีย์เดิม → อัปเดตทับ ไม่เพิ่มแถว (ยอดและสถานะเปลี่ยนตาม),
  เลขที่เดียวกันแต่คนละลูกค้า → แยกเป็นคนละใบ
- `seed_data.sql` โหลด 167 ใบ / 282 บรรทัดสินค้า / 58 ลูกค้า / 126 สินค้า และรันซ้ำแล้วจำนวนไม่เพิ่ม
- มุมมองประวัติราคาให้คำตอบถูกต้อง (อายิโนะโมะโต๊ะ 18 ใบตั้งแต่ 2564 ราคา 900 → 1,000 → 1,200 บาท/ตัน)
- `main.py` และ `db.py` ผ่านการคอมไพล์ไวยากรณ์

**ยังไม่ได้ทดสอบ** — การรันเซิร์ฟเวอร์จริง เพราะสภาพแวดล้อมที่เตรียมชุดนี้ติดตั้ง
`fastapi` / `asyncpg` จาก PyPI ไม่ได้ ให้รันในเครื่องตามขั้นตอนข้างบนก่อน deploy
